## 🎯 Definition

**B-tree** is a self-balancing tree data structure that maintains sorted data and allows searches, sequential access, insertions, and deletions in logarithmic time. Unlike binary search trees, B-tree nodes can have more than two children, making it ideal for systems that read and write large blocks of data, such as databases and file systems.

**Origin:**
- Invented in 1970 by Rudolf Bayer and Edward M. McCreight at Boeing Research Labs
- Originally designed for organizing and maintaining indexes in databases
- Name origin unclear - possibly "Bayer-tree", "Balanced", "Broad", or "Boeing"
- Published in paper "Organization and Maintenance of Large Ordered Indices"
- Became fundamental to database systems and file systems
- Still the dominant data structure for disk-based indexing

**Key Characteristics:**
- **Self-Balancing** - All leaf nodes at same depth
- **Multi-way** - Nodes can have many children (not just 2)
- **Sorted** - Keys within nodes are sorted
- **Disk-Optimized** - Minimizes disk I/O operations
- **Logarithmic** - O(log n) for all operations

**Key Principle:**
> "B-trees are optimized for systems that read and write large blocks of data. By storing many keys per node, B-trees minimize the number of disk accesses needed to find any key, making them ideal for databases and file systems where disk I/O is the bottleneck."

**Alternative Formulation:**
> "A B-tree generalizes the binary search tree by allowing nodes with more than two children. This 'wider and shorter' structure reduces tree height, which directly translates to fewer disk seeks - the most expensive operation in storage systems."

### B-Tree vs Binary Search Tree

│  ├───────────────────────────────────────────────────────────┤  │

│                                                                  │

│                                                                  │

│                                                                  │
│  For 1 million keys:                                            │

│  That's 85% fewer disk operations!                              │
│                                                                  │

### 2. Search Operation

```
┌─────────────────────────────────────────────────────────────────┐
│                    B-Tree Search Algorithm                       │
│                                                                  │
│  Search for key = 45                                            │
│                                                                  │
│  Step 1: Start at root                                          │
│  ┌───────────────────────┐                                      │
│  │    [30 | 60 | 90]     │  45 > 30, 45 < 60                   │
│  └───────────┬───────────┘  → Follow pointer between 30 and 60 │
│              │                                                   │
│              ▼                                                   │
│  Step 2: Internal node                                          │
│  ┌───────────────────────┐                                      │
│  │  [35 | 40 | 50 | 55]  │  45 > 40, 45 < 50                   │
│  └───────────┬───────────┘  → Follow pointer between 40 and 50 │
│              │                                                   │
│              ▼                                                   │
│  Step 3: Leaf node                                              │
│  ┌───────────────────────┐                                      │
│  │  [42 | 44 | 45 | 48]  │  Found 45! ✓                        │
│  └───────────────────────┘                                      │
│                                                                  │
│  Total: 3 node accesses = 3 disk reads                          │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

**Search Algorithm (Pseudocode):**

```python
def search(node, key):
    """Search for key in B-tree rooted at node"""
    
    # Find position where key should be
    i = 0
    while i < node.num_keys and key > node.keys[i]:
        i += 1
    
    # Check if found
    if i < node.num_keys and key == node.keys[i]:
        return (node, i)  # Found at position i
    
    # If leaf, key not in tree
    if node.is_leaf:
        return None
    
    # Recurse to appropriate child
    return search(node.children[i], key)

# Time Complexity: O(log_m n) where m = order
# Each node access: O(log m) with binary search, or O(m) linear
# Total: O(m × log_m n) = O(log n)
```

**Insertion Algorithm (Pseudocode):**

```python
def insert(tree, key):
    """Insert key into B-tree"""
    root = tree.root
    
    # If root is full, split it first
    if root.num_keys == MAX_KEYS:
        new_root = Node(is_leaf=False)
        new_root.children[0] = root
        split_child(new_root, 0)
        tree.root = new_root
        insert_non_full(new_root, key)
    else:
        insert_non_full(root, key)

def insert_non_full(node, key):
    """Insert into node that is guaranteed not full"""
    i = node.num_keys - 1
    
    if node.is_leaf:
        # Shift keys and insert
        while i >= 0 and key < node.keys[i]:
            node.keys[i + 1] = node.keys[i]
            i -= 1
        node.keys[i + 1] = key
        node.num_keys += 1
    else:
        # Find child to recurse into
        while i >= 0 and key < node.keys[i]:
            i -= 1
        i += 1
        
        # Split child if full before recursing
        if node.children[i].num_keys == MAX_KEYS:
            split_child(node, i)
            if key > node.keys[i]:
                i += 1
        
        insert_non_full(node.children[i], key)

def split_child(parent, index):
    """Split full child at given index"""
    full_child = parent.children[index]
    new_child = Node(is_leaf=full_child.is_leaf)
    
    mid = MAX_KEYS // 2
    
    # Move upper half of keys to new child
    new_child.keys = full_child.keys[mid + 1:]
    full_child.keys = full_child.keys[:mid]
    
    # If not leaf, move children too
    if not full_child.is_leaf:
        new_child.children = full_child.children[mid + 1:]
        full_child.children = full_child.children[:mid + 1]
    
    # Insert median key into parent
    parent.keys.insert(index, full_child.keys[mid])
    parent.children.insert(index + 1, new_child)
```

## 💻 Implementation Example

### B-Tree Node and Basic Operations (Python)

```python
class BTreeNode:
    """B-tree node implementation"""
    
    def __init__(self, t, is_leaf=True):
        self.t = t              # Minimum degree
        self.keys = []          # Keys
        self.children = []      # Child pointers
        self.is_leaf = is_leaf  # Is leaf node?
    
    @property
    def is_full(self):
        return len(self.keys) == 2 * self.t - 1
    
    @property
    def is_minimum(self):
        return len(self.keys) == self.t - 1


class BTree:
    """B-tree implementation"""
    
    def __init__(self, t):
        """
        Initialize B-tree with minimum degree t.
        - Each node has at most 2t-1 keys
        - Each node has at least t-1 keys (except root)
        - Each non-leaf has at most 2t children
        """
        self.t = t
        self.root = BTreeNode(t)
    
    def search(self, key, node=None):
        """Search for key in B-tree"""
        if node is None:
            node = self.root
        
        # Find first key >= search key
        i = 0
        while i < len(node.keys) and key > node.keys[i]:
            i += 1
        
        # Found?
        if i < len(node.keys) and key == node.keys[i]:
            return (node, i)
        
        # Leaf - not found
        if node.is_leaf:
            return None
        
        # Recurse to child
        return self.search(key, node.children[i])
    
    def insert(self, key):
        """Insert key into B-tree"""
        root = self.root
        
        # Root is full - must split first
        if root.is_full:
            new_root = BTreeNode(self.t, is_leaf=False)
            new_root.children.append(self.root)
            self._split_child(new_root, 0)
            self.root = new_root
        
        self._insert_non_full(self.root, key)
    
    def _insert_non_full(self, node, key):
        """Insert into node guaranteed not full"""
        i = len(node.keys) - 1
        
        if node.is_leaf:
            # Insert key in sorted position
            node.keys.append(None)  # Make room
            while i >= 0 and key < node.keys[i]:
                node.keys[i + 1] = node.keys[i]
                i -= 1
            node.keys[i + 1] = key
        else:
            # Find child to recurse into
            while i >= 0 and key < node.keys[i]:
                i -= 1
            i += 1
            
            # Split child if full
            if node.children[i].is_full:
                self._split_child(node, i)
                if key > node.keys[i]:
                    i += 1
            
            self._insert_non_full(node.children[i], key)
    
    def _split_child(self, parent, index):
        """Split child at index"""
        t = self.t
        child = parent.children[index]
        
        # Create new node for right half
        new_node = BTreeNode(t, is_leaf=child.is_leaf)
        
        # Median key goes up to parent
        median_key = child.keys[t - 1]
        
        # Right half keys go to new node
        new_node.keys = child.keys[t:]
        child.keys = child.keys[:t - 1]
        
        # If not leaf, split children too
        if not child.is_leaf:
            new_node.children = child.children[t:]
            child.children = child.children[:t]
        
        # Insert median and new child into parent
        parent.keys.insert(index, median_key)
        parent.children.insert(index + 1, new_node)
    
    def traverse(self, node=None):
        """In-order traversal (returns sorted keys)"""
        if node is None:
            node = self.root
        
        result = []
        for i in range(len(node.keys)):
            if not node.is_leaf:
                result.extend(self.traverse(node.children[i]))
            result.append(node.keys[i])
        
        if not node.is_leaf:
            result.extend(self.traverse(node.children[-1]))
        
        return result


# Example usage
btree = BTree(t=3)  # Order 5 (2*3-1 = 5 max keys)

# Insert keys
for key in [10, 20, 5, 6, 12, 30, 7, 17]:
    btree.insert(key)

# Search
result = btree.search(12)
print(f"Found 12: {result is not None}")  # True

# Traverse (sorted order)
print(btree.traverse())  # [5, 6, 7, 10, 12, 17, 20, 30]
```

## 💡 When to Use B-Trees

### Use B-Trees When:

✅ **Disk-Based Storage**
- Databases and file systems
- Data too large for memory
- Minimizing disk I/O is critical

✅ **Large Datasets**
- Millions to billions of records
- Index structures
- Key-value stores

✅ **Range Queries**
- Finding all keys in a range
- Sorted data traversal
- Min/max operations

✅ **Balanced Performance**
- Need guaranteed O(log n)
- No worst-case degradation
- Predictable latency

### Don't Use B-Trees When:

❌ **In-Memory Only**
- Binary search trees simpler
- Cache-friendlier alternatives exist
- Hash tables if no range queries

❌ **Append-Only Workloads**
- LSM trees better for writes
- B-trees have write amplification
- Consider log-structured storage

❌ **Simple Lookups**
- Hash tables O(1) average
- No ordering needed
- Small datasets

## ⚠️ Common Pitfalls

### 1. Wrong Order Selection

```
❌ Problem: Order too small
   - Tree too tall
   - Too many disk reads
   - Wasted potential

❌ Problem: Order too large  
   - Node doesn't fit in memory page
   - Wasted space in sparse nodes
   - Complex node management

✅ Solution: Match order to disk block size
   Order = (Block Size - Overhead) / (Key Size + Pointer Size)
   
   Example: 4KB block, 8-byte keys, 8-byte pointers
   Order ≈ 4096 / 16 ≈ 256
```

### 2. Not Using B+ Tree for Range Queries

```
❌ Problem: Using B-tree for sequential scans
   - Must do in-order traversal
   - Jumps between internal and leaf nodes
   - Poor cache performance

✅ Solution: Use B+ tree
   - All data in leaves
   - Leaves linked together
   - Sequential scan = follow links
```

### 3. Ignoring Fill Factor

```
❌ Problem: 50% minimum fill wastes space
   - Half of allocated space unused
   - More nodes = more disk reads

✅ Solution: Tune fill factor
   - Bulk loading: fill to 100%
   - Write-heavy: lower fill (room for inserts)
   - Read-heavy: higher fill (fewer nodes)
```

## ✅ Best Practices

### Design

✅ **Do:**
- Choose order based on disk block size
- Use B+ trees for range queries
- Consider workload (read vs write heavy)
- Plan for growth (pre-allocation)

### Implementation

✅ **Do:**
- Keep hot nodes in memory (buffer pool)
- Use binary search within nodes
- Implement proper locking for concurrency
- Handle duplicate keys appropriately

### Optimization

✅ **Do:**
- Bulk load sorted data (bottom-up construction)
- Defragment periodically
- Monitor tree height and node utilization
- Use prefix compression for string keys

## 🎓 Summary

### Key Takeaways

1. **B-tree** is a self-balancing tree optimized for disk-based storage
2. **Multi-way nodes** reduce tree height and disk reads
3. **All operations** are O(log n) - search, insert, delete
4. **Self-balancing** through splits and merges keeps tree optimal
5. **Order selection** should match disk block size
6. **B+ tree** variant stores data only in leaves with linked list
7. **Widely used** in databases (indexes) and file systems
8. **Invented 1970** by Bayer and McCreight, still dominant today
9. **Trade-off** vs hash tables: slower lookup, but supports ranges
10. **Height** typically 3-5 levels even for billions of keys

### B-Tree Decision Framework

```
Should you use a B-tree?

├── Data stored on disk (not RAM)?
│   ├── Yes: B-tree likely optimal
│   └── No: Consider simpler structures
│
├── Need range queries or sorting?
│   ├── Yes: B-tree (or B+ tree)
│   └── No: Hash table may be better
│
├── Dataset size?
│   ├── Large (GB+): B-tree shines
│   └── Small: Overhead may not pay off
│
├── Workload pattern?
│   ├── Read-heavy: B-tree excellent
│   ├── Write-heavy: Consider LSM tree
│   └── Mixed: B-tree good balance
│
└── Need concurrent access?
    ├── Yes: Use B-tree with proper locking
    └── No: Simpler implementation OK
```
